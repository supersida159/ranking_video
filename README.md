## 1. Overview

This system delivers real-time video rankings by efficiently processing user interactions. It leverages a microservice architecture to ensure scalability and high performance. User events (such as views, likes, and comments) are processed asynchronously via Kafka, while real-time data is served from Redis with MySQL as the persistent store.

## 2. Architecture Overview

The system architecture is divided into several key layers:

### 2.1 User Interaction Layer (Gateway)
- **Purpose:** Receives HTTP requests from the frontend.
- **Endpoints:**
  - `POST /interact`  
    Example payload:
    ```json
    {
      "user_id": "u1234567",
      "video_id": "v7654321",
      "action": "like"
    }
    ```
  - **Swagger UI:** Available at `GET /swagger/*any` for API documentation and testing.

### 2.2 Processing Layer
- **Interactive Service:**  
  Validates and processes user actions for multiple event types (views, likes, etc.), using Go generics, and publishes events to Kafka with efficient batch updates.
- **Calculate Service:**  
  Acts as a Kafka consumer that updates video statistics in the database and increments scores in Redis sorted sets.
- **CronJob Service:**  
  Runs daily to persist scores to the database for historical tracking and deletes expired data.
- **SSE Service:**  
  Serves real-time video rankings using Server-Sent Events (SSE). Retrieves rankings from Redis and falls back to MySQL if necessary.

### 2.3 Data Storage Layer
- **Events Database:**  
  Stores raw user interaction logs.
- **Main Database:**  
  Contains video metadata.
- **Video Count Database:**  
  Stores counters and overall scores.
- **Redis (Sorted Sets):**  
  Provides fast score retrieval for real-time ranking.

### 2.4 Message Bus
- **Kafka:**  
  Enables asynchronous, decoupled communication among services.

## 4. System Workflow

1. **User Interaction:**  
   Users interact via the frontend (views, likes, comments).
2. **Event Handling:**  
   - The **Interactive Service** validates user inputs and publishes events to Kafka.
   - The **Calculate Service** consumes these events, updating counters and scores in both MySQL and Redis.
3. **Real-Time Updates:**  
   - The **SSE Service** streams updated rankings to clients in real time.
   - Data is primarily retrieved from Redis, with MySQL as a backup.
4. **Daily Batch Processing:**  
   - The **CronJob Service** runs at the end of each day to persist daily scores and clean up old data.

## 5. Data Structures

### 5.1 Redis Data Structure
- **Global Rankings:**  
  Stored in sorted sets with keys formatted as `rank:global:{videoID}`.
- **Daily Rankings:**  
  Stored in sorted sets with keys formatted as `rank:daily:{videoID}`.

### 5.2 Database Structure
- **Event Tables:**  
  Dedicated tables for each event type (likes, views, etc.).
- **Score Tables:**  
  - One table to record cumulative video scores.
  - Additional tables to save daily scores (e.g., 7–30 days of data).

## 9. Setup Instructions

### 9.1 Configuration
All services load their environment using a shared YAML configuration file.

⚠️ Use `config.sample.yaml` as a template only. Do not store real secrets (e.g., passwords, tokens) in version control.

#### Steps to use config:

1. Copy the sample config to a working file:

```bash
cp config.sample.yaml config.yaml
```

2. Edit `config.yaml` as needed for your local environment:

```yaml
# General environment configuration
ENVIRONMENT: "Development"
HTTP_PORT: 8090
GRPC_PORT: 8889
AUTH_SECRET: "your-auth-secret"
SECRET_KEY: "your-secret-key"

# Database Configuration
DATABASE_URI: "root:password@tcp(localhost:3308)/video-ranking?parseTime=true"
DATABASE_TIMEOUT: 5

# Redis Configuration
REDIS_URI: "redis:6379"
REDIS_PASSWORD: ""
REDIS_DB: 0

# Kafka Configuration
KAFKA:
  KAFKA_BROKERS: ["localhost:9092"]
  KAFKA_RETRY: 3
  KAFKA_CONSUMER_OFFSET_RESET: "earliest"
  KAFKA_PRODUCER_REQUIRED_ACKS: 1
  KAFKA_ENABLE_TLS: false
  KAFKA_VERSION: "2.8.0"
  KAFKA_TIMEOUT: 3000
```

3. Add `config.yaml` to `.gitignore`:

```
# Sensitive local config
config.yaml
```

### 9.2 Docker Compose
Before running services locally, make sure all required containers are up:

```bash
docker-compose up -d
```

This starts:
- Kafka
- Redis
- MySQL

To check logs if something fails:

```bash
docker-compose logs -f
```
